# AI 활용 기록: PR 관리 앱

## 사용자 요청

사용자는 "PR 목록·검사 결과·승인을 한 화면에서 보는 관리 앱"이 목적이라고 정정했다.
요구사항을 다시 정리한 뒤 `https://github.com/jaezero/AIPRGATE.git`를 제공하고
앱 구현에 "진행해"라고 지시했다.
자동화만 구축한 상태를 관리 앱 완성으로 표현하지 않는 것이 핵심이다.

## 생성 범위

OmO 부모 에이전트가 상태 모델·ViewModel·Compose 화면·메인 진입점·
샘플 진입점·회귀/화면 테스트·검증 스크립트·문서를 생성했다.
독립 API 작업은 GitHub REST 전송·파싱과 JVM 테스트를,
독립 인증 작업은 device flow·Keystore 보관과 JVM/기기 테스트를 생성했다.
부모는 반환 소스와 테스트를 읽고 통합했다.
재개 세션의 `PI_MODEL`은 `gpt-6.1-sol`로 직접 확인했다.
복구한 독립 검토의 도구 결과에는 `gpt-6-astra`가 표시됐다.
최종 독립 코드 검토는 도구 기록의 `gpt-5.6-sol`이 수행했고 차단 사항 없이 APPROVE했다.
최종 100장 화면 검토도 같은 모델 계열의 별도 검토자가 수행했다.
처음에는 빈 변경 파일 화면과 늘어난 상태 배지를 차단 사항으로 보고했다.
부모가 해당 PNG를 직접 열어 보니 내용이 정상이었고, 검토자도 12장을 한 장씩
다시 열어 묶음 읽기의 결과를 잘못 대응시킨 것이라고 정정했다.
최종 판정은 차단 사항 없는 PASS/APPROVE다(`.omo/evidence/st_01a1761f-gate-review.md`).
두 AI 검토 모두 사람의 GitHub 리뷰·승인이 아니다.
그 외 이전 생성 작업의 모델은 확인한 정보가 없어 추정하지 않는다.
이 기록은 입력과 적용 결과의 요약이며 원본 대화 전사본은 아니다.

## 구현 판단과 수정

- 현재 Android/Kotlin/Compose/Material 3와 Room 샘플을 유지했다.
- 앱 등록이 없어도 공개 조회를 시작하고 개인 토큰 인증을 사용할 수 있게 했다.
  device flow는 사용자가 제공할 공개 Client ID를 사용하며 비밀키를 앱에 넣지 않는다.
- 리뷰·병합은 실제 GitHub API로 구현하되 도구로 실제 리뷰·병합을 실행하지 않았다.
- API check의 `html_url`보다 Actions 실행을 식별하는 `details_url`을 우선하도록 수정했다.
- 목록·상세 읽기 취소, 조회 중 push, 승인 직전 head/base 변경을 회귀 테스트했다.
- 제출 이후 조회 실패와 불확실한 전송 결과를 성공으로 추정하지 않게 했다.
- 기존 테스트·샘플 데이터·정책·검사 코드를 삭제하거나 검사를 약화하지 않았다.
- 첫 실행기의 Windows 경로 인수 오류와 ADB 한글 경로 전송 오류는 실행 방법을 바꿔 해결했다.
- 첫 확인창 캡처는 전환 중 화면이었다. 고정 sleep 대신 기기의 애니메이션을 끈
  상태와 Compose/PixelCopy의 실제 렌더 완료 신호로 최종 캡처를 다시 생성한다.
- 실제 앱의 익명 조회에서 GitHub가 관리용 `allow_*` 설정을 생략하는 것을 확인했다.
  해당 응답으로 단일 회귀 테스트를 추가하고 수정 전 exit 1을 보존했다.
  선택적 필드는 권한·병합 방법을 허용하지 않는 것으로 읽되 공개 조회는 성공하도록 수정했고,
  수정 후 전체 테스트가 통과했다.
- 관리 앱의 한국어 문장 줄바꿈·날짜 표시와 단일 스크롤을 적용했다.
- 중단된 두 검토는 공급자 사용량 제한으로 최종 판정을 내리지 못했다.
  부분 검토를 통과로 계산하지 않고 다른 검토 경로로 복구했다.
- 복구 검토의 두 차단 문제를 부모가 직접 수정했다.
  취소된 인증의 늦은 완료가 새 로그인 상태를 지우는 문제는 deferred 이벤트로
  수정 전 실패를 재현하고 인증 세대·작업 순서·저장 취소 복구·로그아웃 정리를 고쳤다.
  같은 base SHA의 다른 브랜치로 변경된 PR은 저장소·번호·head/base·브랜치를
  담은 불변 확인 대상으로 막고, 화면 갱신 시 이전 확인창도 닫게 했다.
- 직접 캡처에서 비활성 글자 대비와 좁은 확인창의 한국어 줄바꿈을 확인하고,
  관리 앱 전용 17/15sp 본문과 공통 비활성 색상·짧은 확인 문장으로 수정했다.
  원래 샘플의 타이포와 기능 코드는 바꾸지 않았다.
- 최종 implementation-8에서 JVM 72건, 휴대폰·넓은 화면 각각 계측 17건이 통과했다.
  두 테마의 100장 캡처를 최종 소스 이후 생성했다.
- 증거 JSON의 파일명-keyed 소스 해시가 Gitleaks generic key로 오탐되어,
  실제 해시 값과 기존 결과를 보존하면서 `{path, sha256}` 배열로 바꿨다.
  보안 정책·제외 규칙을 변경하지 않았고 후속 실제 스캔은 발견 0이었다.

## 1인 운영 모드 (2026-10-26)

사용자가 "본인이 하고 본인이 승인하도록" 요청했다. AI는 GitHub가 작성자 자기 승인을
거부한다는 점과 요구사항 미충족을 설명했고, 사용자가 1인 운영 모드를 선택했다.
OmO 부모 에이전트가 자기 검토 표식·병합 조건·확인창, 1인 보호 정책과 `--solo` 감사,
대응 JVM·기기·검사 도구 테스트를 생성했다. 팀용 정책과 기존 검사는 약화하지 않았다.
자기 검토를 다른 사람의 승인으로 표시하거나 집계하지 않는다.

## 적용 결과의 추적

실제 적용 파일은 `app/src/main/java/com/example/aiprgate/{github,auth,management}/`,
`MainActivity.kt`, `SampleActivity.kt`, `ui/theme/Theme.kt`와 대응 테스트다.
검증 snapshot의 `inputs`는 적용 소스와 테스트의 SHA-256을 기록하고,
APK 해시와 JUnit XML로 실행 결과를 연결한다. Git 커밋을 만들지는 않았다.
수정 전 공개 응답 결함은 `public-response-before-fix`,
인증 경합은 `auth-race-before-fix`의 실패 로그로 구분한다.
원본 생성과 중간 수정 전체는 로컬 에이전트의 도구·대화 기록에 있으며,
이 문서가 전사본이나 최초 코드 전체를 복제한 자료라고 하지 않는다.
사람이 직접 코드를 수정하거나 GitHub에서 승인했다는 증거는 아직 없다.
사용자의 구현 지시는 코드 리뷰·실계정 인수 승인으로 계산하지 않는다.

## 증거와 제한

실제 Gradle·JUnit·Lint·기기 테스트 로그와 화면은 `docs/results/management-app/`에 보존한다.
기기 UI 테스트 데이터는 합성 데이터라고 표시하며 실제 PR·승인·병합 증거로 쓰지 않는다.
실제 공개 PR은 별도의 읽기 전용 수동 검증으로 구분한다.
개인 토큰·실제 device code·앱 비밀키를 문서나 캡처에 기록하지 않는다.
API/상태 테스트의 문자열은 실제 권한이 없는 시험 입력이다.
독립 AI 검토는 실제 사람의 GitHub 승인으로 계산하지 않는다.
