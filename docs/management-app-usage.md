# PR 관리 앱 사용법

## 시작 화면

앱 실행 시 PR 관리 화면에서 `jaezero/AIPRGATE`의 열린 PR을 조회한다.
공개 저장소는 로그인 없이 읽을 수 있다.
열림 / 닫힘·병합 / 전체 필터, 더 불러오기와 새로고침을 제공한다.
검사·승인 요약은 실제 API에서 별도로 가져오며 미조회·실패를 통과로 표시하지 않는다.

`연결 설정`에서 다른 `owner/repository` 또는 GitHub 저장소 주소를 입력할 수 있다.
앱으로 돌아올 때와 새로고침 시 최신 상태를 다시 조회한다.

## 사용자 인증

리뷰와 병합은 본인의 GitHub 사용자 인증이 필요하다. 두 가지 방법이 있다.

### 등록한 GitHub App으로 로그인

관리자가 GitHub App을 등록하고 필요한 저장소 접근 권한과 device flow를 설정한다.
앱의 연결 설정에 **공개 Client ID**를 입력하고 로그인 코드를 요청한다.
GitHub 인증 화면을 열어 코드를 입력하고 본인 계정으로 허용한다.
앱이 GitHub가 지정한 간격으로 상태를 확인하고 사용자를 검증한 뒤 세션을 저장한다.
코드와 인증·취소 버튼이 화면 아래에 있으면 아래로 스크롤한다.
이전 인증을 취소하고 다시 시작해도 늦은 이전 응답이 새 연결을 덮어쓰지 않는다.
client secret이나 앱 비밀키를 APK에 포함하지 않는다.
현재 배포용 GitHub App/Client ID는 제공받지 않아 미리 넣지 않았다.

### 개인 access token으로 연결

앱 등록 전에는 본인이 발급한 개인 토큰을 앱의 비밀번호 입력란에 직접 넣어 연결할 수 있다.
토큰을 채팅·코드·문서·PR·로그에 붙여넣지 않는다.
앱은 `/user` 조회 성공 후에만 인증된 사용자로 표시한다.

Fine-grained 개인 토큰은 대상 저장소 접근과 필요한 권한을 선택한다.
PR 읽기·리뷰에는 Pull requests, 검사 조회에는 Checks 및 Commit statuses의 읽기,
병합 요청에는 Contents 쓰기 등 사용하려는 작업에 맞는 권한이 필요하다.
계정의 저장소 역할과 조직의 추가 승인·정책도 적용된다.
권한 부족을 앱이 자체적으로 우회하지 않는다.

토큰은 Android Keystore AES/GCM으로 암호화하여 앱의 백업 제외 경로에 저장한다.
인증 입력은 화면 상태 복원 데이터에 넣지 않는다.
`이 기기에서 로그아웃`은 로컬 암호문과 메모리 세션을 지운다.
GitHub 토큰 자체를 폐기하는 작업은 GitHub 설정에서 별도로 수행한다.

## PR 상세

- **요약:** 제목·작성자·브랜치·현재 커밋과 본문을 표시한다.
  AI 사용·테스트 근거는 PR 본문 원문을 읽고 검토한다.
- **변경:** 변경 파일과 patch를 표시한다. 긴 diff는 가로 스크롤한다.
  바이너리·GitHub가 생략한 patch는 원문 링크로 확인한다.
- **검사:** head 및 현재 병합 예상 커밋의 check runs와 커밋 상태를 표시한다.
  검사 이름·상태·출력 요약과 GitHub 로그 링크를 제공한다.
- **리뷰:** 리뷰 이력과 대상 커밋, 의견·수정 요청·승인, 병합 조건을 표시한다.

PR 본문·diff·검사 출력은 실행하지 않고 텍스트로 표시한다.
외부 링크는 HTTPS의 github.com만 연다.
GitHub가 제공하지 않는 로그 요약을 만들어내지 않는다.

## 승인·병합

의견·수정 요청·승인은 확인창에서 대상 PR과 커밋을 확인한 뒤 제출한다.
자기 PR은 의견만 제출할 수 있다. 작성자 외 승인만 최신 승인 수에 포함한다.
확인 대상에는 저장소·PR 번호·head SHA·base SHA·대상 브랜치를 함께 보존한다.
제출 직전에 PR을 다시 조회하며 이 대상이 바뀌면 재검토를 요구한다.
같은 SHA를 가리키는 다른 브랜치로 PR이 변경돼도 기존 확인으로 제출하지 않는다.
화면 갱신으로 대상이 바뀌면 열린 확인창을 닫아 다시 확인하도록 한다.
리뷰 의견은 실패 시 유지한다.

병합은 다음 조건을 앱에서 보수적으로 확인하고 GitHub에 다시 요청한다.

- 인증된 사용자·저장소 쓰기 권한·열린 비초안 PR.
- GitHub의 병합 가능 상태가 확인됨.
- `pr-info`, `build-test`, `quality`, `secrets`, `quality-gate`가 같은 Actions 실행에서 통과.
- 최신 커밋에 대한 작성자 외 승인 또는 작성자 자기 검토(1인 운영), 미해결 수정 요청 없음.
- 사용 가능한 병합 방법.

검사 이름은 현재 로컬 검사 기반의 이름이다.
원격 저장소의 예전 `app-check`, `quality-check`, `secret-check`는 결과 자체를 보여주지만
새 정책의 필수 체크를 충족한 것으로 임의 변환하지 않는다.
GitHub 워크플로우와 보호 설정을 맞추는 일은 별도 외부 적용 작업이다.

병합 요청에는 확인한 head SHA를 보내며 최종 성공은 GitHub 응답으로 결정한다.
자동 승인·자동 병합·규칙 bypass는 사용하지 않는다.
요청 뒤 연결이 끊기면 성공을 추정하거나 자동 재전송하지 말고 GitHub에서 실제 결과를 확인한다.

## 1인 운영 모드

저장소에 구성원이 한 명뿐이면 다른 사람의 승인을 받을 수 없다.
GitHub는 작성자가 자기 PR을 승인(Approve)하는 것을 거부한다.
그래서 작성자는 리뷰 탭의 `자기 검토 완료`로 검토 기록을 남긴다.

- 확인창에서 PR 번호·커밋과 체크리스트(요구사항 적합성, 테스트 근거, AI 사용 기록,
  민감정보 없음, 권한·저장·예외 처리)를 확인한다.
- 앱은 `[AiPrGate 작성자 자기 검토]` 표식과 체크리스트, 입력한 의견을
  현재 head SHA에 대한 GitHub 의견 리뷰로 제출한다.
- 새 커밋이 올라오면 이전 자기 검토는 인정하지 않는다. 다시 검토해야 한다.
- 자기 검토는 `최신 승인` 수에 포함하지 않고 이력에 `자기 검토`로 표시한다.
- 자동 검사 통과와 다른 병합 조건은 그대로 적용한다.

GitHub 보호 설정은 `policy/main-protection-solo.json`을 사용한다.
필수 승인 수만 0이고 `quality-gate` 필수 검사·관리자 적용·우회 금지는 유지한다.

```sh
bun tools/pr-gate/github-protection.mjs --file policy/main-protection-solo.json --solo
GITHUB_TOKEN=... bun tools/pr-gate/github-protection.mjs --repo jaezero/AIPRGATE --solo --apply
```

제한:

- 자기 검토는 앱의 병합 조건에서만 강제한다. GitHub 웹에서는 자기 검토 없이도
  검사만 통과하면 병합할 수 있다. GitHub가 작성자의 의견을 병합 조건으로 쓰지 못하기 때문이다.
- 요구사항의 "작성자 외 승인"(AC-10, EVD-05, GOV)과 다른 팀원의 재실행(NFR-09)은
  1인 운영으로 충족되지 않는다. 기록에는 자기 검토로 남기고 타인 승인으로 적지 않는다.
- 팀원이 합류하면 `policy/main-protection.json`(승인 1명·최신 push 재승인)으로
  보호를 교체한다. 앱은 코드 변경 없이 GitHub의 병합 가능 상태를 따른다.

## 보존된 샘플

PR 목록 아래 `검증 대상 · 할 일 샘플 열기`로 기존 앱에 들어간다.
원래 Room 코드와 `learning-tasks.db`를 유지한다.
Android Back으로 관리 앱으로 돌아온다. 앱 데이터 삭제·재설치를 초기화 방법으로 사용하지 않는다.

## 검증의 구분

실제 공개 PR 조회는 실제 저장소 데이터로 확인한다.
회귀 테스트의 리뷰·승인·병합은 fake API를 사용하여 외부 쓰기를 만들지 않는다.
화면 검증용 합성 데이터는 일반 앱의 기본 모드로 제공하지 않는다.
실제 사용자 인증·두 사람 승인·보호를 지키는 병합 인수는 계정과 사용자 동작이 필요하다.
해당 실적이 없는 상태를 연동 인수 완료로 표현하지 않는다.

## 실제 연동 인수에 필요한 준비

1. 관리자: 대상 저장소에 설치·허용한 GitHub App의 공개 Client ID와 device flow 설정을
   준비한다. 또는 각 사용자가 필요한 저장소 권한의 개인 토큰을 앱에 직접 입력한다.
   앱 등록이나 토큰 공유는 이 구현 작업에서 대신 실행하지 않았다.
2. 관리자: 원격에 남은 이전 워크플로우와 로컬 `.github/`, `policy/`, `tools/pr-gate/`를
   검토하고, 별도 승인한 게시·보호 설정 작업으로 검사 이름을 일치시킨다.
3. 작성자와 다른 리뷰어: 각자 앱에서 연결한 계정을 확인하고 테스트용 PR을 선택한다.
   검사 실패 → 코드 수정·push → 최신 검사 → 수정 요청·리뷰·승인 → 병합을 수행한다.
4. 각 제출의 실제 PR·head SHA·검사 run/attempt·리뷰 ID·병합 응답을 기록한다.
   네트워크 오류 후에는 재제출 전에 GitHub의 실제 반영 여부를 먼저 확인한다.

APK는 `app/build/outputs/apk/debug/app-debug.apk`이다.
이 PC에서는 `scripts/verify-management.ps1 -Mode build`로 APK·JUnit·Lint를,
실행 중인 에뮬레이터에서는 `-Mode device`로 기기 검사를 재현한다.
Windows PowerShell에서 실행하며 JDK·경로 인코딩 처리는 스크립트가 설정한다.
정확한 측정치와 한계는 `docs/results/management-app/verification.md`에 있다.
